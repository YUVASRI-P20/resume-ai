## Canonical foundation
`app/` at the project root is based on **ZIP 5**, because ZIP 5 is the latest coherent evolution of the authentication/interview/coding/feedback/roadmap foundation and includes the migration history through `0003_feedback_and_roadmap.py`.

ZIP 1 and ZIP 4 were not blindly overlaid because they contain duplicate versions of the same foundation files. Blind overlaying would silently overwrite newer implementations.

## Preserved unique modules
- `modules/module_3_4_resume_analyzer/` — ZIP 2 resume upload/parsing + AI resume analysis implementation.
- `modules/module_5_6_11_12/` — ZIP 6 optimizer/readiness/recruiter/notification implementation.

## Important integration note
The ZIPs were generated by different AI sessions and use **different database/session architectures**:
- Root foundation: SQLAlchemy async (`AsyncSession`) + repository/service architecture.
- Resume module: SQLAlchemy sync (`Session`) + a separate legacy `app.core.database` layout.
- ZIP 6: SQLAlchemy sync with placeholder authentication/database dependencies.

Therefore, simply copying every file into the same `app/` directory would create import conflicts and could break authentication, database models, and startup. The unique modules are preserved here instead of being falsely presented as fully runtime-integrated.

## Recommended next integration step
Use this combined project as the single source package and perform one controlled integration pass:
1. Move resume models/repositories/services to the root async database architecture.
2. Replace ZIP 6 placeholder `get_current_user()` and `get_db()` with the root authentication/database dependencies.
3. Register all module routers in the root `app/api/v1/router.py`.
4. Merge all ORM models into `app/models/__init__.py` and Alembic metadata.
5. Create one consolidated migration chain.
6. Deduplicate and consolidate `requirements.txt` and `.env.example`.
7. Run import checks, tests, and startup checks before connecting the frontend.

This structure intentionally avoids destructive overwrites and keeps every unique implementation available for the final integration pass.
